# 2026.09.0 — onboarded to the fleet guards; the CDN supply chain is pinned and verified

Technical record. User-facing notes: `src/release_notes/2026.09.0.md`.

## Versioning changed: SemVer → CalVer

`1.0.5` → **`2026.09.0`** (`YYYY.0M.MICRO`). luxmark is a deployed application, and the fleet's app convention is CalVer — the version answers *when was this built* rather than implying a compatibility contract luxmark does not offer (it is a page, not a library anyone links against). Published image tags move with it. The README version badge now **derives from the git tag** instead of hardcoding a literal, so it can no longer disagree with `VERSION`.

## Supply chain: every external dependency is pinned and hash-verified

The page loads 16 third-party resources from CDNs — code that executes in a visitor's browser with full access to the page and its `localStorage`. Before this release:

- **2 were completely unpinned.** `cdn.jsdelivr.net/npm/marked/marked.min.js` resolves to whatever the registry calls latest *at request time*. Measured during this work: that path was serving **marked 15.0.12** while marked's latest was **18.0.13** — so luxmark was one CDN cache expiry away from a major-version jump with breaking API changes, arriving with no commit and no deploy. Both are now pinned (`marked@15.0.12`, `marked-footnote@1.4.0`) to the versions actually running, so present behaviour is frozen and a bump is a deliberate, reviewed act.
- **0 of 16 carried an SRI hash.** All 16 now carry `integrity="sha384-…"` **and** `crossorigin="anonymous"` — both halves, because SRI is not enforced on a cross-origin request without `crossorigin`, which makes a hash alone decorative. Hashes were computed from the actual fetched bytes.

Google Fonts' `css2` endpoint is deliberately excluded: it returns a UA-specific stylesheet and can carry neither a version nor a stable hash by construction.

## Rendered markdown is now sanitized before it reaches the DOM

`marked.parse()` output (plus KaTeX markup spliced in afterwards) went straight to `previewElement.innerHTML` with **no sanitizer anywhere in the repo**. marked is not a sanitizer — it removed its `sanitize` option and documents DOMPurify as the answer.

Scope, stated honestly: the only content source today is what the user types locally, and the audit found no URL-parameter, file-open, paste or drag-drop path, so an injection was **self-inflicted**, not a live vulnerability. It stops being self-inflicted the moment anything can supply a document — share-by-URL, open-a-file, paste-as-HTML — and at that point unsanitized markup can read every saved document out of `localStorage`. `DOMPurify.sanitize()` now sits **at the sink** (the one place every byte that becomes live HTML passes through), so that feature can be added without also having to remember this.

KaTeX lays glyphs out with inline `style` and highlight.js keys off `class`; DOMPurify permits both by default and MathML/SVG are in its default profile, so math and code survive. **This needs a browser confirmation** — file-level tests cannot verify rendering.

## A test suite, where there was none

`make test` previously just *started the container*. It now runs a real suite (`node:test`, no npm install, no build step — matching how this repo ships) that locks the properties above: every external dependency pinned, every one hash-verified with `crossorigin`, markdown sanitized before `innerHTML`, and the declared JS globals still matching the script tags they describe. A guard against vacuous passes is included — the suite fails if the tag scan finds fewer resources than really exist. Container-running moved to `make serve`.

These are deliberately not rendering tests; that requires a browser. They cover what fails *silently*.

## Guards, build and deploy

- **All three guards wired** (`.luxarch.toml` / `.luxlint.toml` / `.luxaudit.toml`) with pinned versions and one `make check` gate: `guard-version-check honest lint test arch audit gitleaks`. `guard-version-check` is fatal, so nobody works off a stale guard.
- **luxarch gained a `static-web` kind** for this repo (luxarch 0.173.0) — the layered Python packs had nothing to say about a browser app, and forcing `library` would have made ~37 Python rules pass vacuously.
- **Provenance**: canonical `BUILD_VERSION`/`BUILD_COMMIT`/`BUILD_TIMESTAMP` build args and OCI `version`/`revision`/`created`/`source` labels. `version.json` now carries the real commit instead of `"n/a"`.
- **One `compose.yaml`** replaces `compose.yml` + `compose.prod.yml`. The image is built outside compose and pulled by an explicit `${TAG:?}` — no `build:` stanza and no `:latest`, because a floating deploy tag means a restart can silently change the running version. `.env.example` is the committed template; `.env` is gitignored.
- **Shared fleet buildx builder**, GC-capped, instead of a per-project one.
- **Claude Code hooks installed from the guard image** (18 files), never hand-written.

## Code hygiene

- 8 unused `catch (err)` bindings → optional catch binding (`catch {`). Every one is a genuine fallback path; binding a name nothing reads was what eslint flagged.
- Two unnecessary regex escapes removed from the inline-math and currency patterns, **proven equivalent on 14 cases** before the change — de-escaping inside a character class can silently alter meaning.
- `hljs` and the other CDN libraries are now declared in `[js].globals`, which is what makes eslint's `no-undef` meaningful: an undeclared global is a real typo, not noise.

## Known red, deliberately left lit

Nothing is hidden behind a deferral. Reds that remain are tracked, not silenced.
