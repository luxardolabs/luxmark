# 2026.10.0 — 2026-10-10

The CSP no longer grants script `unsafe-inline`/`unsafe-eval`; the base image is patched; every release is now scanned before it can be published.

## Notes

- **No deploy steps beyond pulling the tag.** Self-hosters set `TAG=2026.10.0` in `.env` and `docker compose up -d`. No data or `localStorage` change.
- **Published to GHCR only** (`make release-ghcr`), as 2026.09.0 was. The local-registry and Docker Hub targets are unchanged and unused; whether to keep the Hub targets is LUXMARK-13.
- Open guard escalations, none blocking (no red is lit): LUXMARK-18 (luxaudit `--image-archive` exits 0 on an unreadable archive), LUXMARK-19 (canonical image-block / gitleaks release gate fails open), LUXMARK-20 (`repo.deploy_tag_is_immutable` only reads the fail-open refusal shapes, so `publish_version` carries both).
- LUXMARK-11: the hosted site is not yet on this version.
- **First release through the gated `publish_version` path**: the candidate is pushed to the private registry as `candidate-<commit>`, every platform of its digest is scanned with luxaudit, and only that digest is promoted to `ghcr.io/luxardolabs/luxmark:2026.10.0`.

## Infra / Ops

- **Release gate (`publish_version`, used by `docker-push-local` / `-hub` / `-ghcr`).** One `set -e` shell, so `make -i` cannot skip it:
  - refuses a dirty tree, and refuses when `git status` itself fails (a distrusted checkout used to read as clean);
  - refuses an existing `:VERSION`, failing closed on any lookup error but the registry's not-found, and names `make release-hub` / `make release-ghcr` to resume an interrupted multi-registry release;
  - builds the multi-arch candidate into the private registry only, pins its digest, scans every platform in `$(PLATFORM)` against this repo's `.luxaudit.toml` (`$(CURDIR)`, not the caller's `$(PWD)`), refuses an empty archive, then `imagetools create`s `:VERSION` from that digest.
  - An `/adversarial` pass reproduced 8 breaks in the first version of this gate; 7 fixed, each locked by `tests/release.test.js` (9 cases fail against 56a9e11). The 8th is luxaudit's (LUXMARK-18).
- **Dockerfile: `apk upgrade --no-cache`** in the nginx:alpine stage. The candidate scan found 10 fixable HIGH OS CVEs (incl. pcre2 CVE-2026-103111, tiff CVE-2026-4775); 0 after.
- **`docker-build-local` / `build-local`** tag only the bare `luxardolabs/luxmark:local`; a registry-qualified name is never built without being pushed.
- **`docker-tag-latest-*` retag instead of rebuild** (6d7b525): `imagetools create` points `:latest` at the existing multi-arch `:VERSION` manifest. The rebuild produced a second image with `revision=unknown`, and `-local` dropped arm64.
- **Makefile committed** (6459f4b), environment-agnostic; registry host in gitignored `Makefile.local` (`Makefile.local.example` committed). `compose.yaml` → `compose.yml`.
- **Guards:** luxarch 0.173.1 → 0.278.0, luxlint 0.53.1 → 0.63.1, luxaudit 0.7.0 → 0.13.2 over four repulls. Every emitted asset current (gitleaks v12, claude-pointer v7, buildx-setup v2, changelog-guide v3, release-notes-guide v2, all seven skills, hooks). gitleaks v12 adds a binary-file pass and restricts commit identities to the fleet account.
- **`make test` runs on `node:22`** (was `node:22-alpine`) for the `make` and `git` that `tests/release.test.js` drives.

## Fixes

- **CSP `script-src`** is `'self' https://cdnjs.cloudflare.com https://cdn.jsdelivr.net` (d05f866). Nothing used the dropped grants: every `<script>` loads by `src`, no inline handlers, no `eval`/`new Function` in `src/js` or the 12 pinned CDN files. Verified in headless Chromium under the served header: 0 violations across every UI flow (theme, copy ×4, downloads incl. PDF via html2canvas + jsPDF, KaTeX, highlight.js); an injected inline script is blocked. Locked by `tests/csp.test.js`.
- **Compose healthcheck** probes `http://127.0.0.1:8080/` (1d96fcc). busybox wget resolved `localhost` to `::1`, nginx listens IPv4-only, so the container reported unhealthy while serving. Locked by `tests/compose.test.js`.
