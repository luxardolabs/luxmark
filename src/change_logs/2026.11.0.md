# 2026.11.0 — 2026-11-05

Replaces the vulnerable 2026.10.0 image in prod; the runtime user can no longer write the served app; releases and deploys run through the emitted fleet blocks, refusing any input the makefiles did not set.

No application code changed (`src/` is identical to 2026.10.0). Every change is in the image, the deploy, the release path or the guards.

## Features

- **`make prod-deploy`** (LUXMARK-11): syncs `compose.yml` to the prod node over a jump host, pins `.env` TAG, runs `up -d --wait`, and fails unless the live `/version.json` reports VERSION. It refuses an unpublished VERSION, and refuses `make -i` (4025837).
- **The release is the emitted image block** (v16 → v22, LUXMARK-24/35). It builds a multi-arch (amd64 + arm64) candidate into the private registry, scans every platform by digest against this repo's `.luxaudit.toml`, creates `:VERSION` on GHCR from that digest, then creates the GitHub Release. There is no `:latest` (LUXMARK-26 is still on hold).
- **`make smoke`** probes the deployed stack (c870751).

## Refactors

- The guards run through the emitted guard-run block (v7), and the gate is check-gate (v3), whose legs are lint, test, arch, audit and gitleaks (eb9a57a, 61611f4, 18311c1).
- A parse-time input guard (Makefile, after the emitted blocks) refuses `-i`, `-e`, command-line variables, and registries or CHECK_LEGS from the environment, on the release, gate and deploy goals (089b1be, 4025837). The emitted blocks now refuse the same inputs on their own.

## Infra / Ops

- **Pre-deploy:** none. **Post-deploy:** `make prod-deploy` with VERSION 2026.11.0. It syncs this release's `compose.yml`, which adds `oom_score_adj: -500`; the container is recreated.
- **Image:** the served files are root-owned and read-only to nginx, which owns only `/var/cache/nginx`, `/var/log/nginx` and `/var/run` (repo.runtime_user_cannot_write_code). The base is pinned to `nginx:1.31-alpine` with `apk upgrade`. A `test` stage is added for `make test-build`; local builds use `--target production`.
- **Build context:** `.dockerignore` excludes every secret class (dotenv, credentials, `*.pem`, SSH keys, `.git`, bytecode) and every `.gitignore` pattern at any depth (repo.build_context_hygiene).
- **compose.yml:** the service is renamed `web` → `luxmark` (container `luxmark-web`). It publishes on 127.0.0.1 by default (`LUXMARK_BIND`), and has the `luxmark` alias on the shared `luxardolabs` network for the OVH edge. It also sets `oom_score_adj: -500`.
- **Registries:** the registry build cache was dropped (owner decision, 15ccaf0), and so were the Docker Hub targets (b837c3c). Candidates live only in the private registry; releases go to GHCR.
- **Guards:** luxarch 0.278.0 → 0.344.0, luxlint 0.63.1 → 0.74.0, luxaudit 0.13.2 → 0.16.0, over several bumps. The hook set is re-emitted and now includes shared-machine.
